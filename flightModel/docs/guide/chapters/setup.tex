\section{Prepare the shell}

Do this step in each new shell, before you use a script:

\begin{shell}
source /usr/lib/openfoam/openfoam2412/etc/bashrc
\end{shell}

If you do not do this step, all scripts stop with the message
\val{source the OpenFOAM bashrc first}.

\begin{caution}
Put the mesh directories and the run directories outside \file{/mnt/c}. On WSL,
that file system makes the input and output of OpenFOAM several times slower.
\end{caution}

\section{Prepare the computer for a sweep}\label{sec:prepare-computer}

A sweep runs for days. The cost of each run is a measurement
(\cref{sec:measurement}). Do these steps before you start a sweep. Steps 1 to 4
need \cmd{sudo}.

\begin{steps}
\item Set the CPU profile to \val{performance}. Other profiles decrease the clock
  frequency, and the cost of the run does not compare with other runs.
\begin{shell}
echo performance | sudo tee /sys/firmware/acpi/platform_profile
\end{shell}
  The setting is lost when the computer starts again.
\item Let \cmd{perf} count the cycles and the energy, permanently:
\begin{shell}
echo kernel.perf_event_paranoid=0 | sudo tee /etc/sysctl.d/90-perf.conf
sudo sysctl --system
\end{shell}
  With \val{1}, \cmd{perf} counts the cycles but not the energy. With \val{2} or
  more, it counts neither.
\item On a laptop, make sure that the computer does not suspend when you close the
  lid. Set \ent{HandleLidSwitch=ignore} in \file{/etc/systemd/logind.conf}, or keep
  this command open in a terminal for the duration of the sweep:
\begin{shell}
systemd-inhibit --what=handle-lid-switch:sleep --why="CFD sweep" sleep infinity
\end{shell}
\item Make sure that the memory has sufficient cooling. Keep the air inlets open
  and lift the rear of a laptop. On \texttt{nemepad} a memory module reached
  \unit{83}{\textdegree C} (limit \unit{85}{\textdegree C}) with the fans in automatic mode.
\item Stop other heavy programs. Two runs on one socket share the memory
  bandwidth.
\end{steps}

\begin{caution}
On a ThinkPad, a reload of the module \cmd{thinkpad_acpi} (for example to control
the fans) can set the CPU profile to \val{custom}, at about \unit{2}{GHz}. Do step 1
again after a reload.
\end{caution}

\section{Build this guide}\label{sec:build-guide}

The guide needs LuaLaTeX, BibTeX, the TeX Gyre fonts and the packages of TeX Live
\texttt{latex-extra}. The diagrams need Node.js 20 or later, the npm package
\texttt{pele} and Google Chrome.

\begin{steps}
\item Go to the directory of the guide:
\begin{shell}
cd flightModel/docs/guide
\end{shell}
\item If you changed a diagram, install Pele once and render the diagrams:
\begin{shell}
npm install
make figures
\end{shell}
  \file{figures/render.mjs} renders each \file{figures/src/*.mmd} (Mermaid) to SVG
  with Pele, and prints it to \file{figures/pdf/*.pdf} with headless Chrome. Set
  \cmd{CHROME} to use another Chrome executable.
\item Compile the guide:
\begin{shell}
make
\end{shell}
  Result: \file{aconcagua-user-guide.pdf}. \cmd{make} runs \cmd{lualatex},
  \cmd{bibtex} and \cmd{lualatex} two more times.
\item Commit the source, \file{figures/pdf/} and the PDF together.
\end{steps}
